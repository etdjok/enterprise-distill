# 企业蒸馏保真度评分卡

> 借鉴 huashu-nuwa fidelity-scorecard，适配企业场景。
> 答题 Agent 和评分 Agent 必须是**两个独立 Agent**。

---

## 评分前准备

1. 明确评分对象：哪家企业的蒸馏产出？（画像 / Skill / 对比报告）
2. 加载该企业的 Phase 1 调研原始素材（`references/research/01-06.md`）—— 评分 Agent 要对照验证
3. 如果是 Skill 模式，准备 3-5 个测试问题（已知决策 + 边缘场景）

---

## 五个评分维度

| # | 维度 | 权重 | 说明 |
|---|------|------|------|
| 1 | **战略逻辑还原度** | 30% | 心智模型 + 启发式 与企业实际决策的匹配度 |
| 2 | **组织基因完整度** | 25% | 架构/激励/文化三层 + 决策模式 是否都有 |
| 3 | **边缘诚实度** | 20% | 遇到企业没表态的问题是否标注推断 |
| 4 | **来源透明度** | 15% | 每条关键结论是否有来源标注 |
| 5 | **可操作性** | 10% | 用这个 Skill/画像 能否在新问题上生成有用的分析 |

---

## 各维度评分标准（详细）

### 维度 1: 战略逻辑还原度（30%）

| 分数 | 标准 |
|------|------|
| 9-10 | 心智模型通过三重验证，每个有 ≥ 2 个跨场景证据；决策启发式与调研原始素材高度匹配；护城河地图与 Agent 1 调研结论完全一致 |
| 7-8 | 心智模型基本通过三重验证，部分模型证据略弱；启发式有案例支撑但跨场景性不足 |
| 5-6 | 心智模型疑似通过三重验证但证据链不完整；部分启发式是"通用商业道理"而非企业特有 |
| 3-4 | 心智模型未通过三重验证（只有 1 个场景证据）；启发式多为通用商业建议 |
| 1-2 | 心智模型是编造的；启发式与调研素材无关 |

**测试方法**（对照 `references/research/02-decisions.md` 和 `references/research/01-strategy.md`）：
- 列出 Phase 2 提炼的每个心智模型
- 在调研原始素材中查找对应的"跨决策场景证据"
- 检查：证据是否真的跨场景？模型是否真的从行为反推而非从声明直接提取？

### 维度 2: 组织基因完整度（25%）

| 分数 | 标准 |
|------|------|
| 9-10 | 架构演化有完整时间线 + 关键拐点驱动力；激励机制覆盖薪酬/股权/绩效；文化代码三层全有 + Gap 分析；决策模式覆盖权力/容错/失败处理/信息流 |
| 7-8 | 架构演化基本完整；激励机制覆盖主要部分；文化代码三层有但 Gap 分析不够深；决策模式覆盖 3/4 维度 |
| 5-6 | 架构演化只有大时间节点没拐点；激励机制只有薪酬；文化代码只有表面层和声称价值，没有反推的基本假设 |
| 3-4 | 只有零散信息没有结构化；文化代码只有表面层 |
| 1-2 | 组织基因部分缺失大半 |

**测试方法**（对照 `references/research/03-organization.md` 和 `references/research/06-timeline.md`）：
- 检查 Phase 2 的 Layer 2 是否覆盖了所有四个子模块（架构/激励/文化/决策模式）
- 特别是文化代码的 Layer 3（基本假设）是否真的是从 Gap 反推的，还是编造的

### 维度 3: 边缘诚实度（20%）

| 分数 | 标准 |
|------|------|
| 9-10 | 已知测试：方向+细节全对；边缘测试：推断合理+明确标注"框架推断"；至少有 1 个维度诚实标注了"信息不足" |
| 7-8 | 已知测试：方向对，细节有小偏差；边缘测试：推断基本合理但标注不够清晰 |
| 5-6 | 已知测试：方向基本对，关键决策理由有偏差；边缘测试：推断合理但完全没标注不确定性 |
| 3-4 | 已知测试：方向有明显偏差；边缘测试：编造而非推断 |
| 1-2 | 全部编造；已知测试方向错误 |

**测试方法**：
1. **已知测试**：选 3 个该企业**公开决策过的历史事件**，看 Skill/画像 是否能准确还原决策理由
2. **边缘测试**：选 1 个该企业**没公开表态过但相关的问题**（如"亚马逊会进入某某赛道吗"），看输出是否：
   - 推断合理（能用心智模型推导出结论）
   - 明确标注"这是框架推断，非企业官方立场"
3. **诚实边界检查**：是否反复强调"公开信息 ≠ 真实决策逻辑"？是否标注了至少一个维度的信息不足？

### 维度 4: 来源透明度（15%）

| 分数 | 标准 |
|------|------|
| 9-10 | 每条心智模型/启发式/反模式都有来源标注；区分了一手/二手/推测；关键引用有出处；没有编造金句 |
| 7-8 | 主要结论有来源标注，次要细节缺标注；来源类型基本清楚 |
| 5-6 | 约一半关键结论有来源；不区分一手/二手 |
| 3-4 | 只有少数结论有来源；大量结论无法溯源 |
| 1-2 | 几乎没有来源标注 |

**测试方法**（对照 `references/research/` 的 6 个 md 文件）：
- 随机抽查 10 条 Phase 2 提炼结论
- 每条能否在调研原始素材中找到对应来源？
- 金句/原话是否有出处？

### 维度 5: 可操作性（10%）

| 分数 | 标准 |
|------|------|
| 9-10 | 用这个 Skill/画像 分析一个**全新的商业问题**，输出的分析比通用 AI 回答**有实质差异**——体现了这家企业的独特视角；研究维度从心智模型自动推导 |
| 7-8 | 分析有用，但和通用 AI 的差异不大；研究维度是通用搜索指引 |
| 5-6 | 分析有道理但比较空泛；无法体现企业独特视角 |
| 3-4 | 分析混乱或偏离主题 |
| 1-2 | 无法用于实际分析 |

**测试方法**：
1. 准备一个全新的商业问题（如"AI 时代，这家企业应该怎么调整招聘策略"）
2. 用蒸馏产出回答
3. 同时用通用 AI 回答
4. 对比：蒸馏产出的回答是否因为**用了这家企业的心智模型**而有独特见解？

---

## 评级

| 总分 | 等级 | 含义 |
|------|------|------|
| 90-100 | A | 精品级：可以开源发布 |
| 75-89 | B | 生产级：内部使用没问题 |
| 60-74 | C | 可用级：核心框架成立但有明显薄弱处 |
| 40-59 | D | 需迭代：回到 Phase 2 调整提炼方向 |
| 0-39 | F | 失败：心智模型编造或证据不足，不建议交付 |

---

## 评分执行清单

- [ ] 答题 Agent 和评分 Agent 是两个独立 Agent
- [ ] 评分 Agent 能访问 Phase 1 调研原始素材（`references/research/01-06.md`）
- [ ] 已知测试的 3 个问题选的是企业**公开过的决策**（不是编造的）
- [ ] 边缘测试的问题**企业确实没公开表态过**（不是假装的）
- [ ] 可操作性测试用的是**全新问题**（不是调研中出现过的）
- [ ] 每个维度都有具体的分数 + 扣分理由（不只是给个总分）
- [ ] 评分完成后，输出结构化的评分报告（每个维度的分数 + 理由 + 改进建议）
